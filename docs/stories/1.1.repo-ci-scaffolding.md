# Story 1.1: Repo & CI Scaffolding

## Status

Approved

## Story

**As a** developer,
**I want** a repo scaffold with lint/test CI wired from the first commit,
**so that** every subsequent story inherits a working quality gate instead of retrofitting one later.

## Acceptance Criteria

1. Repository contains a Python 3.11+ FastAPI project scaffold matching the structure in Technical Assumptions (`apps/incident-copilot/`, `platform/`, `docs/`).
2. A GitHub Actions workflow runs on every push/PR — lint (ruff) + unit tests (pytest) — and fails the build on any failure.
3. README documents how to run the service locally and how to run tests.
4. Repo is pushed to a public GitHub repository.

## Concepts You Need

_(Read this before starting — these are the ideas this story actually exercises, not generic background.)_

- **Why CI from commit #1, not "later":** every later story (1.2 onward) assumes a working lint+test gate already exists. If Story 1.1 skips CI "to move faster," every subsequent story either has to retrofit it (expensive, and tempting to skip forever) or ships without one. This is the single most common gap between a demo-grade repo and a production-grade one — and it's cheap to get right now, expensive to add later.
- **Monorepo with two independently-installable packages (`apps/incident-copilot/` and `platform/`):** `platform/` exists as its own package — not because M1 needs that separation internally, but because M2–M6 will add it as a dependency later. This is a real architectural decision with a one-sentence justification (Architecture doc, Source Tree section) — notice how a structural choice this early is driven by a plan 5 products ahead, not by this story's own needs.
- **Why `uv` + a committed lockfile, not bare `pip install`:** reproducibility. "Works on my machine" is the thing CI exists to rule out — a lockfile pins exact versions so CI and your machine install identically.
- **Note on this story's place in the roadmap:** this is sprint **S1** ("Repo init + FastAPI webhook"). There's no AWS cert lab tied to this specific sprint — the first lab tie-in (G1, Bedrock Converse) lands in **Story 2.1**, not here. Worth knowing so you don't go looking for an AWS angle that doesn't exist yet.

### Coding Standards (relevant to this story)

- Languages & Runtimes: Python 3.12, dependency management via `uv` [Source: architecture/coding-standards.md#core-standards]
- Style & Linting: `ruff`, config in `pyproject.toml`, enforced in CI — not a local-only convention [Source: architecture/coding-standards.md#core-standards]
- Test Organization: `pytest`; `tests/unit/` mirrors `src/` package structure 1:1; `tests/integration/` is flat, named by capability [Source: architecture/coding-standards.md#core-standards]
- No deviations from PEP 8 naming conventions [Source: architecture/coding-standards.md#naming-conventions]

### Testing

- Test file location: `apps/incident-copilot/tests/unit/`, mirroring `src/` 1:1; `platform/tests/unit/` likewise [Source: architecture/test-strategy-and-standards.md#unit-tests]
- Framework: pytest 8.x [Source: architecture/test-strategy-and-standards.md#unit-tests]
- This story only needs ONE trivial smoke test (the FastAPI app object exists / `/health` returns 200) — do not write tests for unimplemented future features; AAA pattern applies even to this trivial test [Source: architecture/test-strategy-and-standards.md#unit-tests]
- CI must run lint, test, and dependency-audit as separate jobs so a failure is attributable to a specific tier [Source: architecture/test-strategy-and-standards.md#continuous-testing]

### Technical Constraints

- No deviation from the pinned versions in Tech Stack without flagging it — if a pinned version (e.g. FastAPI 0.136.3) is no longer installable, note this in Completion Notes rather than silently substituting a different version [Source: architecture/tech-stack.md]
- This is a greenfield project with no starter template — the Source Tree document is the scaffold's specification, not a suggestion [Source: architecture/introduction.md#starter-template-or-existing-project]
